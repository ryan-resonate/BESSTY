BESS group / array creator

Two scenes below: (1) the wizard modal that opens when the user clicks + BESS group, and (2) the on-map representation of a placed group with rotation + drag affordances. Static mockup; meant for a design pass before we lock in the data model.

v2 changes from review: dropped the Origin text field (group now lands in the middle of the map and the user drags it; use a shapefile import for precise unit placement). Added Repeat row × N per row so one row template can stamp many copies with the same gap between each. Renamed spacing labels for clarity. Removed corner-scale handles from the on-map view. Removed "Bake to individual sources" — groups are permanent; exports (shapefile / SoundPlan) flatten the parametric group into one record per physical unit automatically.

Scene 1 · Wizard modal

Opens on + BESS group (a new button in the Sources tab next to "+ BESS"). Also re-opens via Edit group in the right-click menu shown in Scene 2. Left half = parametric form (the "row sequence"); right half = live top-down preview that re-renders ~200 ms after each keystroke. Each row in the sequence has: pattern (an ordered list of unit chips: BESS / Inverter / Transformer), pattern × N (repeat that pattern within one row), row × N (stamp this same row N times — gap-to-next applies between each copy and after the last copy if another row follows), spacing (edge-to-edge between adjacent units within the row), and gap-to-next-row (edge-to-edge from this row's footprint to the next row's footprint). "Two close rows, wide gap, two more rows" is one row with row×2 + gap 8 m, then a placeholder row with gap 0 and no units, then another row × 2. Or three separate row entries — same effect either way.

Scene 2 · On-map view (placed group, selected)

Once applied, the group appears on the map as a translucent bounding rectangle with the individual units inside. When selected: a rotation handle floats above the top edge, a translate handle (the yellow centre dot) lets you drag the whole array. Numeric spacing changes go through the wizard — no corner-scale handles, intentionally, because per-axis scaling of edge-to-edge gaps is more confusing than helpful. Right-click anywhere on the group opens the contextual menu shown; double-click re-opens the wizard with the saved parameters.

Resolved design decisions (v2)

  • Layout model = rows with explicit patterns + row × N stamp. Each row template can be repeated N times (gap-to-next applies between every copy). Reusable identical rows = bump row × N; near-identical rows = duplicate template button then tweak.
  • Preview = live, debounced ~200 ms after the last keystroke.
  • Per-unit edits survive regeneration. Hand-edited units (e.g. BESS shifted 3 m for a fence) keep their position; the wizard shows a "N units modified" chip with a "reset to parametric" affordance.
  • Groups are permanent. No "bake to individual sources" escape hatch. Exports (shapefile / SoundPlan / receivers CSV) automatically flatten the parametric group into one record per physical unit — the downstream tool never sees the group as a concept, just the materialised sources.
  • Origin isn't typed in the form. New groups drop in the centre of the map view; user drags into place via the centre handle. For precise placement, use Import locations… with a shapefile instead.
  • On-map handles = rotation handle (above top edge, Shift snaps to 15°) + centre translate handle only. No corner-scale handles — per-axis spacing changes happen in the wizard with numbers.

Still open / proposed for implementation

  1. Unit footprint dimensions: the materialiser needs to know each unit's width/length to compute edge-to-edge spacing in metres. Proposal: add footprintM: { widthM, lengthM } to CatalogEntry, seeded with sensible defaults per kind (BESS Megapack 2 XL = 5.1 × 1.7 m; Inverter Sungrow SG3300 = 2.0 × 1.5 m; Transformer = 4.0 × 4.0 m). Users can override per-entry in the Catalog screen.
  2. "Placeholder" row for asymmetric gaps: if a row's pattern is empty, it acts as a pure spacer (just adds gap-to-next). Useful for "wide aisle between blocks" without inventing block syntax. The v2 scene-1 description hints at this; let me know if it's worth surfacing as an explicit "Spacer" row type in the UI.
  3. Drag-reorder of row templates: drag handle on each row card (⋮⋮) is shown. Confirm we want this in v1 or defer (move via up/down arrows instead).
  4. Catalog scope picker per unit chip: each unit in the pattern references a catalog entry. The mockup chips show names only; implementation needs a dropdown per chip (global / personal / local). Easy but a UI consideration when chips get small.
